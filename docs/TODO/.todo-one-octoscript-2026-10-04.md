## 2. 参考实现：flutter-samples 怎么做的

> 用户原话："像 Octoscript-Makepad 里面的一个示例项目 flutter-samples 就是用 xx.octoscript 写的，selection xx.octoscript 在 Octoscript-Makepad/components/flutter"

### 2.1 flutter-samples 的形态（per `Octoscript-Makepad/apps/flutter-samples/`）

| 文件 | 作用 |
|------|------|
| `Cargo.toml` | 一个标准 cargo 包，依赖 `octoscript-widgets`、`octoscript-render`、`octoscript-makepad` |
| `src/main.rs` | 8 行桌面入口，转 `flutter_samples::app_main()` |
| `src/lib.rs` | 480 行 Rust：baked-in 28 个 `.octoscript`（用 `include_str!` 拼接）+ App struct + tap dispatch + nav |
| `BAKED` | 固定顺序拼接的 kit：`_kit.octoscript` 优先，samples 排序，**`_index.octoscript` 最后**（router） |
| `DEVICE_PATH` | `/data/local/tmp/flutter_samples.octoscript`（hot-reload override） |
| `ROUTE_PATH` | `/data/local/tmp/flutter_samples.route`（route 切换触发） |
| `DIAG_PATH` | `/data/local/tmp/flutter_samples.diag`（mount 报告） |
| `components/flutter/*.octoscript` | 27 个屏目录对应 1 个 `.octoscript` 文件 + 108 routes + `_kit.octoscript` + `_index.octoscript`（router） |

**关键点**：
1. **一个 Rust 包** = 一个 app，不是"两个入口两个路径"
2. **所有 UI 在 `.octoscript` 里** —— 没有 `.splash`、没有 `.card`、没有 imperative host.call 包装
3. **状态/tap** 用 `sget(key, default)` + `tapto: "set:m3_c1=!"`（`components/flutter/README.md` §"Controls that are controls"）
4. **router** 在 `_index.octoscript` 里：if/else if 链读 `st.route` 选屏，最后 `node` 作为脚本值
5. **kit 共用**：`octoscript-widgets` 注册 `mod.widgets.*` 的 themed variants，屏 `.octoscript` 通过 `mod.prelude.widgets.*` 引用
6. **运行**：`cargo run -p flutter-samples`（桌面），或 `cargo makepad android run -p flutter-samples --release`（手机）

### 2.2 selection 屏（cupertino_gallery "picker" 段）

用户提到的 "selection xx.octoscript" 实际指的是 `components/flutter/cupertino_gallery.octoscript` 里的 selection/picker 部分。核心模式：

```text
fn c_lane(col, key, dflt) {
    if st.backend == "arkui" {
        // 系统 picker（ArkUI）
    }
    // makepad fallback: 用一列文本 + tap 选
    let rows = []
    let ci = 0
    for opt in col {
        let active = sget(key, dflt) == ci
        rows.push({t: "row", fillw: 1, h: 44, tapto: "set:" + key + "=" + ci, ...})
        ci = ci + 1
    }
    return {t: "column", c: rows}
}
```

要点：
- **状态**：`sget(key, default)` 读 store，第一次 seed 而不是 default
- **触发**：`tapto: "set:m3_radio=2"` 字符串编译成 `set:<key>=<value>` action（kit 内部）
- **导航**：tap 也可发 `tapto: "cupertino_gallery/picker"` 之类走 route（routing signal 写到 mounted tree 内的 `nav_signal` label）

### 2.3 finance-brief 对齐 flutter-samples 的关键差异

| 维度 | flutter-samples | 当前 finance-brief |
|------|----------------|-------------------|
| DSL | `.octoscript` 全文 | `.splash` + `.card`（两套 DSL） |
| 状态 | `sget(key, default)` + `tapto: "set:..."` | `nav.current` + `host.call` + `loaded_X` flag |
| 数据获取 | （kit demo，无真实数据） | host.call → 9 Rust adapter（必须保留） |
| Workflow | （无） | `bundle/workflow.octoscript`（7 fn 已写但未挂） |
| Theme | `components/material/catalog.octoscript` | `bundle/kit/*.octoscript`（144 个 palette/axis 文件） |
| K 线图 | （无） | 屏 6 K 线，用 `mod.plot.CandlestickChart`（`docs/KLINE-WIDGET.md`） |

**结论**：finance-brief 比 flutter-samples 复杂（多了真实数据源 + workflow + K 线图），但**DSL 形态完全可以对齐** —— 把 main.splash 拆成多个 `.octoscript`，把 `.card` 并入对应屏文件。

### 3.3 渲染管线（对齐 octoscript-makepad 完整管线）

```
*.octoscript (12 屏 + kit + workflow + main)
    ↓ octoscript-render VM (makepad-script)
    ↓ UiNode tree
    ↓ octoscript-makepad::to_makepad_ui (或 design::to_makepad_ui)
    ↓ makepad dialect string
    ↓ Splash VM (main VM via with_vm, 不走 isolate)
    ↓ Makepad Widget Tree + Native Widgets (GPU + touch + resize)
```

**vs Path 1**：跳过 octoscript-ui-l0 check/realize/lower（因为 .octoscript 已经是 makepad dialect 形态，不是 L0 ledger）
**vs Path 3 lite**：不走 L0 ledger pipeline（finance-brief 的屏有 imperative state + workflow，需要 L1）

**数据流**：
```
.octoscript 屏（declarative + sget/tapto）
    ↓ host.fetch("cap.X", {args})  ← DSL 内调用
    ↓ apps/finance-brief/src/datasources.rs 解析 + dispatch
    ↓ 调 native/src/adapters/<x>.rs 实际 fetch
    ↓ cache 写入（与原 card-host 一致）
    ↓ sget 读到 → 屏重 render
```
