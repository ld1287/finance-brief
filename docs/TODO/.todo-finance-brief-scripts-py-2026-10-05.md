## 设计约束

- **stdlib only**：只准用 `argparse` / `json` / `subprocess` / `urllib.request` / `pathlib` / `shutil` / `sys` / `os` ——**不允许 `requests`、不引入新依赖**。
- **CLI 兼容**：每个 .py 保持和对应 .sh 完全一致的入参、输出格式、退出码。
- **跨平台**：
  - 路径：`pathlib.Path` 跨平台拼接
  - curl → `urllib.request.urlopen(url, timeout=N)`
  - cargo → `subprocess.run(..., check=True, cwd=...)`
  - python 命令：在 Windows 上优先 `python`，Unix 上用 `python3`
- **shebang**：`#!/usr/bin/env python3`（Unix 可直接 `./foo.py`；Windows 由 `python` 解析）
- **不删除 .sh**：先并存，verify 通过后由 verify agent 统一删。
- **不改 bundle/、apps/、OctoSense/、makepad/、Octoscript-Makepad/、Octoscript/ 任何源文件**。

## 风险

1. **`install-as-system-app.py` 写 `OctoSense/`** —— 跟原 .sh 行为一致，但提醒 agent 在 dry-run 模式下不要真写。
2. **`OctoSense/` 不存在的环境** —— 原 .sh 用 `[ ! -f "$OCTO/Cargo.toml" ]` 检查，.py 用 `if not Path(octo / "Cargo.toml").exists(): raise SystemExit(1)` 替代。
3. **`urllib.request.urlopen` 抛 `URLError` 时退出码** —— 原 curl 是 exit 7/28，Python 应映射到 7（URLError 通用）或自定义（agent 自决）。
4. **subprocess 的 `cargo build` 输出太多** —— 用 `subprocess.run(..., check=True)`，失败时输出 stderr；正常情况用 `tail_lines=20` 控制输出量。
