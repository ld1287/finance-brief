## 一处偏离原 plan

**`Cargo.toml` 的 `workspace = true` 改为 git rev 显式依赖**。

`flutter-samples` 在 `Octoscript-Makepad` workspace 内部，所以 `makepad-widgets = { workspace = true }` 能解析。`apps/finance-brief/` 在 finance-brief 仓库里，不在该 workspace 里，会失败。已改为显式 git rev（`d4502ef...`）+ 相对 path 指向 `Octoscript-Makepad/crates/`。

## Review 点（按风险从高到低）

### 1. `.octoscript` 语法未编译验证 🔴

`bundle/screens/*.octoscript` 是模仿 `Octoscript-Makepad/components/flutter/*.octoscript` 写的，**未实际跑过**。具体风险：

- `let n = items.len(); for i in n { ... }` — flutter 是 `for e in array`，不是 `for i in n`。可能要 `for i in 0..items.len()` 或换成数组迭代。
- `sget(stk_settings, fb_settings_seed)` — `sget` 第二个参数是 default value，`fb_settings_seed` 是 `{theme: ..., freq_ms: ...}` 对象，可能不接受 object 当 default。
- K-line widget 调用：`mod.plot.CandlestickChart` 的命名待 `finance-brief/docs/KLINE-WIDGET.md` 对一遍。

### 2. `datasources.rs` 是 stub，未接通 native 🟠

`apps/finance-brief/src/datasources.rs` 18 个 `mod.fb.<cap>` 函数目前只 `log!`，没接到 `native/src/adapters/`。`App::script_mod` 调了 `datasources::register_capability_handlers(vm)`，所以 DSL 里 `use mod.fb.*` 能解析，但实际网络 / 缓存调用都没接通。屏幕渲染现在走的是 `_kit.octoscript` 里的 seed data。

### 3. `lib.rs::script_mod` 未注册 `makepad_plot` 🟠

`script_mod!` 块目前只调 `datasources::register_capability_handlers(vm)`，**没有**调 `makepad_plot::script_mod(vm)`。`bundle/screens/kline.octoscript` 里用了 `mod.plot.CandlestickChart`，屏幕渲染时 widget 注册表里没这项，会"not found in scope"。

另外：`apps/finance-brief/` 与 `native/` 的 workspace 关系还没建立，datasources.rs 真去 wire adapter 时需要一个稳定的 import path。

### 4. `README.md` §3 Run 里 `cargo test` 未验证 🟡

`cargo test --manifest-path native/Cargo.toml` 在 main 上是过的（65/65 PASS），但 feat 分支没跑过 — 迁移没动 `native/`，理论应保持，但核心里没底。
