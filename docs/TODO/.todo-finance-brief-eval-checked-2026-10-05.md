## 1. 根因

### 1.1 v10 用了 `eval_with_append_source`，但这个 API 是为增量 source 编辑设计的
代码 `apps/desktop/src/app.rs:62-80`:
```rust
let script_mod = ScriptMod {
    ...
    code: String::new(),   // ← code 字段空着
};
let built_view = cx.with_vm(|vm| {
    let value = vm.eval_with_append_source(   // ← 增量 API
        script_mod,
        &code,                                // ← 实际 code 通过这个参数传
        ...
    );
});
```

`vm.eval_with_append_source` 用 `(file, line, column)` 缓存 body（`makepad/platform/script/src/vm.rs:1617-1633`）。第二次调用：
- `existing_body_id` 命中（同样 file/line/column）
- `prev_len = body.source_len`（第一次的 code 长度）
- `content_changed = code[..prev_len] != body.tokenizer.original[..prev_len]` —— 我们的两个 code 共享 `use mod.prelude.widgets.*\nView{height:Fill, ` 前缀（≈ 41 字符），所以 `content_changed = false`
- 走 L1680 分支：只 tokenize `code[prev_len..]`（**增量字符**），parser 从 checkpoint 继续
- **run_root 重新执行**整个 bytecode —— 但 bytecode 是**原 launcher 的**+**追加的部分 news_list token**，结果是**混合**或只有 launcher 生效

### 1.2 正确模式（calendar / beauty）
两处都用 `vm.eval_checked(sm, ...)`，且 `code` 字段**直接写入** `script_mod.code`:

```rust
// Octoscript-Makepad/apps/kit-host/src/beauty.rs:131-145
let sm = ScriptMod {
    cargo_manifest_path: env!("CARGO_MANIFEST_DIR").into(),
    module_path: module_path!().into(),
    file: file!().into(),
    line: 1,
    column: 0,
    code,                                  // ← code 在这里
    values: Vec::new(),
};
let view = cx.with_vm(|vm| {
    let value = vm.eval_checked(sm, 2_000_000)?;   // ← 完整重求值
    Ok::<_, String>(View::script_from_value(vm, value))
});
```

`vm.eval_checked` 调 `vm.eval(script_mod)` → `vm.eval_with_source` → `add_script_mod` 看到 `effective_code` **变了**（因为新 `code` 不同），会**重置 tokenizer/parser/checkpoint/source_len**（`vm.rs:1512-1518`）。然后 `run_root` 完整执行新 code。

### 1.3 为什么 finance-brief 之前能起来（launcher 显示）
第一次 `eval_with_append_source`：
- body 不存在 → `add_script_mod` 创建空 body
- `body.source_len = 0`
- `content_changed = false`（prev_len=0）
- 走 L1680 分支：tokenize 整个 `code`，parse_streaming 跑全 parse
- run_root 完整执行 launcher bytecode → launcher 显示 ✅

第二次（点击）：
- body 存在 → 复用
- 同上分析，**结果是 launcher 的 bytecode 仍在，news_list token 追加在尾部**
- run_root 重新执行时，主表达式仍返回 launcher View（news_list 部分可能是 malformed 的 garbage）
