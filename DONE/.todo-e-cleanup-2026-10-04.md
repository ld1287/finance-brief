  ```
  ## Summary
  `card-host` with `--stamp` flag silently rewrites `bundle/manifest.json`'s
  `integrity.bundle_blake3` field on disk, even when the user only intended
  to check the bundle's integrity.

  ## Steps to reproduce
  1. `cd finance-brief && ls bundle/manifest.json`
  2. Note digest in `integrity.bundle_blake3`
  3. Add a new file under `bundle/` (e.g. `bundle/test.txt`)
  4. Run `card-host --bundle finance-brief/bundle --allow-unsigned --stamp`
  5. Diff `bundle/manifest.json` — `integrity.bundle_blake3` changed

  ## Expected behavior
  - Without `--stamp`: digest is computed and compared; mismatch should error.
  - With `--stamp`: warning should be printed before rewriting on disk.
  - `hub check` (which appears to invoke `card-host` internally) should never
    modify the manifest on disk.

  ## Actual behavior
  - `card-host --stamp` rewrites silently, only logs "stamped".
  - `hub check` in some configurations appears to call `card-host --stamp`
    implicitly, causing the manifest to drift across simple `hub check` runs.

  ## Environment
  - OctoSense-App-Hub commit: <commit SHA>
  - card-host: `crates/card-host/src/host.rs:80-86`
  - args: `crates/card-host/src/args.rs:27-30`

  ## Suggested fix
  - Add `--stamp` warning message before disk write
  - Make `--stamp` opt-in (default off in non-developer mode)
  - Add `--dry-run` flag for digest verification without rewrite
  - Have `hub check` use `--dry-run` mode, not `--stamp`
  ```
